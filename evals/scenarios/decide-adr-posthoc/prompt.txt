The decision (made in code during implementation, never recorded): instead of the synchronous
POST to the merchant endpoint that sad.md §4 describes, `internal/orders/service.go` now writes an
`order.placed` row into a new `webhook_outbox` table in the SAME transaction as the order
(`migrations/000003_create_webhook_outbox.up.sql`), and a background worker in
`internal/relay/relay.go` drains the table, sends the HMAC-signed webhook and retries with
exponential backoff for up to 24 h. Why: a slow merchant endpoint in the checkout request path
broke the p95 target, and a crash between the order commit and the HTTP call lost webhooks.

Options the team weighed: (a) keep the synchronous POST after commit (the original sad.md §4
plan); (b) transactional outbox table + background relay worker (chosen); (c) publish to a message
broker such as NATS or Kafka.
